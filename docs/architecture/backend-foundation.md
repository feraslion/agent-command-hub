# Agent Command Hub — الأساس الشخصي

## قرار المرحلة

يعتمد المشروع حالياً مساراً تدريجياً داخل البنية الخلفية الموجودة. تصبح المشاريع والمهام والوكلاء وسجل التنفيذ والموافقات والتكاليف بيانات دائمة عبر API محمية، بينما تؤجل بيئة العمل المعزولة والعامل المستقل وPostgreSQL إلى مرحلة التشغيل المستقل. لا توجد في هذه المرحلة صلاحية shell للوكلاء أو تنفيذ خلفي عند إغلاق التطبيق.

## الجداول الأساسية

| المجال | الجداول | الاستخدام |
| --- | --- | --- |
| المشروع والعمل | `projects`، `tasks`، `task_dependencies` | مصدر حقيقة للمشروع ومهامه وتسلسلها |
| الوكلاء والتنفيذ | `agents`، `agent_runs`، `execution_events` | تعريف الوكلاء وتوثيق حالة التشغيل والأحداث |
| المعرفة والمخرجات | `artifacts`، `decisions`، `memory_items` | حفظ المخرجات والقرارات والذاكرة العملية |
| التحكم | `approvals`، `cost_entries`، `model_usage` | الموافقات، كلفة الاستدلال، واستخدام النماذج |

## واجهات المرحلة الحالية

| المجال | القراءة | التعديل |
| --- | --- | --- |
| المشاريع | قائمة المشروع وتفاصيله | إنشاء مشروع شخصي |
| المهام | مهام المشروع | إنشاء مهمة وتحديث حالتها |
| الوكلاء | وكلاء المشروع | تعريف وكيل ضمن المشروع |
| الموافقات | طلبات المشروع | إنشاء طلب واعتماده أو رفضه |
| التكاليف | ملخص التكلفة مقابل سقف المشروع | تسجيل عملية استخدام موثقة |
| الأحداث | سجل المشروع المرتب زمنياً | تسجله عمليات المجال تلقائياً |

## الترتيب المعتمد بعد هذه المرحلة

> قاعدة البيانات → API → Workspace → Agent Runtime → Tools → Sandbox → Task Engine → Orchestrator → Workers/Queue → الوكلاء الأساسية → Memory → Model Router → Git → Realtime → Approval → Security → اختبار مشروع حقيقي.

لا تبدأ المنصة بتنفيذ وكلاء شكلية. بعد استقرار البيانات وAPI، تكون الخطوة التالية إنشاء Workspace مقيّدة لكل مشروع، ثم بناء runtime بسيط لسبعة وكلاء فقط: Orchestrator وPlanner وCoder وQA وDebugger وReviewer وRelease.

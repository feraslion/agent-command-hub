# تفعيل التشغيل المستقل للوكلاء

## المبدأ

لا يصبح الوكيل مستقلاً بمجرد إضافته إلى واجهة الجوال. يلزم فصل **واجهة التحكم** عن **خدمة تنفيذ دائمة**. تظل واجهة Agent Command Hub مكان عرض الحالة والموافقات والتكلفة، فيما يستمر التنفيذ في خدمة خلفية بعد إغلاق الهاتف.

```text
تطبيق الجوال
     │ أوامر وموافقات
     ▼
API + قاعدة البيانات + سجل الأحداث
     │ إنشاء مهمة قابلة للتنفيذ
     ▼
طابور مهام ─── عامل تنفيذ دائم ─── Runtime للوكلاء
                       │                  │
                       │                  ├─ Workspace المشروع
                       │                  ├─ أدوات مقيدة
                       │                  └─ Sandbox لكل تشغيل
                       ▼
                 أحداث، مخرجات، تكلفة، طلبات موافقة
```

## مكونات التشغيل

| المكوّن | مسؤوليته | قاعدة الأمان |
| --- | --- | --- |
| **Workspace** | مجلد دائم منفصل لكل مشروع: `source` و`docs` و`tests` و`artifacts` و`memory` و`logs` | لا يسمح للمهمة بالكتابة خارج مساحة مشروعها |
| **Runtime** | يحول المهمة إلى خطوات لوكلاء محددين، ويحفظ الحالة والـ heartbeat والنتائج | لا يمنح الوكيل صلاحيات أدوات مباشرة؛ يمر عبر بوابة سياسة |
| **Worker** | يستهلك المهمة من الطابور ويستأنفها بعد توقف التطبيق | يعالج مهمة محددة مع قفل ومدة تشغيل وإعادة محاولة محدودة |
| **Sandbox** | ينفذ الشيفرة والاختبارات والأوامر في بيئة عابرة | ملفات مضيفة غير متاحة، صورة أساس مقيدة، مهلة وذاكرة وشبكة مضبوطة |
| **Policy Gateway** | يفحص كل فعل قبل التنفيذ: قراءة أو كتابة أو Git أو شبكة أو نشر | يوقف الأفعال عالية الأثر حتى تصل موافقة صريحة |

## الوكلاء الأولى

ابدأ بسبعة وكلاء فقط: **Orchestrator** و**Planner** و**Coder** و**QA** و**Debugger** و**Reviewer** و**Release**. لا تضف باحثاً أو معماريّاً أو وكلاء متخصصة أخرى قبل أن يثبت المسار الأساسي: خطة ثم تعديل ثم اختبار ثم مراجعة.

| المرحلة | الإدخال | المخرج | الانتقال |
| --- | --- | --- | --- |
| Orchestrator | طلب المستخدم وحالة المشروع | خطة ومهام وتبعيات | Planner |
| Planner | الخطة والسياق | مواصفات تنفيذ قابلة للاختبار | Coder |
| Coder | مهمة وWorkspace | تغيير وملف مخرجات | QA |
| QA | التغيير ومعيار القبول | PASS أو FAIL مع دليل | Reviewer أو Debugger |
| Debugger | تقرير الفشل والسجل | تحليل السبب وإصلاح مقترح | QA |
| Reviewer | المخرجات وتقارير الجودة | APPROVED أو REWORK | Release أو Coder |
| Release | مخرج معتمد | تسليم أو طلب موافقة نشر | المستخدم |

## سياسة الموافقة

| المستوى | أمثلة | السلوك |
| --- | --- | --- |
| تلقائي | قراءة Workspace، تحليل، كتابة اختبار، تشغيل اختبار محلي | ينفذ ويسجل الحدث |
| مراجعة | تغيير تبعية، تعديل واسع، قرار معماري | يوقف الخطوة ويسجل طلب مراجعة |
| موافقة صريحة | حذف، وصول خارجي، Git push، نشر، تغيير أسرار | لا ينفذ قبل قرار المستخدم |

## التفعيل المرحلي

| المرحلة | ما يُبنى | معيار النجاح |
| --- | --- | --- |
| 1. Workspace | خدمة تنشئ مجلد مشروع دائماً وسجل مخرجات | مشروعان لا يستطيعان رؤية ملفات بعضهما |
| 2. Runtime جاف | انتقال حالات المهام وسجل الأحداث بلا أوامر نظام | تظهر دورة المهمة كاملة في التطبيق |
| 3. أدوات مقيدة | قارئ وكتابة ملفات داخل Workspace وتشغيل اختبارات محددة | ينجز Coder + QA تغييراً صغيراً قابلاً للتراجع |
| 4. Sandbox | تشغيل عابر بحدود وقت وموارد وشبكة | فشل أمر لا يؤثر على العامل أو مشروع آخر |
| 5. Worker وطابور | استهلاك مستمر للمهمات، قفل، heartbeat، وإعادة محاولة | تستمر مهمة بعد إغلاق تطبيق الجوال |
| 6. Git وRelease | فرع عمل وملخص diff وبوابة نشر | لا يحدث Push أو نشر بلا موافقة |

## خيارات بيئة التشغيل

| الخيار | النتيجة | الحدود | متى يصلح |
| --- | --- | --- | --- |
| **خدمة دائمة مُدارة** | عامل تنفيذ دائماً في الخلفية، مع قاعدة البيانات وAPI الحالية | مناسبة للأدوات البرمجية الخفيفة، ولا تصلح لحاويات Docker أو أدوات نظام مخصصة | مرحلة Workspace وRuntime جاف وطابور ضمن حدود الخدمة |
| **حاسوب شخصي دائم** | عامل وSandbox على جهازك، من دون اشتراك خادم جديد | يجب أن يبقى الجهاز متصلاً، ويحتاج ضبط وصول ونسخ احتياطي | بيئة شخصية وتجارب أدوات الشيفرة المعزولة |
| **خادم Linux مستقل** | Docker وRedis وWorkers وSandbox معزول على مدار الساعة | يحتاج إعداداً تشغيلياً ومراقبة وتكلفة استضافة | عند الحاجة لاستقلال كامل عن هاتفك وجهازك الشخصي |

> لا تبدأ بحاويات أو صلاحية shell. ابدأ بـWorkspace وRuntime جاف وسجل أحداث. بعد أن تُثبت سياسة الموافقة ومسار المهمة، أضف الأدوات المقيدة ثم Sandbox ثم العامل الدائم.

## القرار المطلوب قبل التنفيذ

حدد بيئة العامل الدائم أولاً: خدمة مُدارة ضمن حدودها، أو جهازك الشخصي المتصل، أو خادم Linux مستقل. هذا القرار يحدد طريقة بناء Sandbox وRedis وGit، ولا يغير واجهة الجوال أو مخطط البيانات الحالي.

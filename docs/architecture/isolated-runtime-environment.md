# بيئة Runtime المعزولة

## الغرض

تفصل هذه الطبقة بين **إدارة الخطط وملفات Workspace** داخل التطبيق وبين **تشغيل شيفرة المستخدم**. لا يصبح أي ملف محفوظ في Workspace قابلاً للتنفيذ لمجرد كتابته أو اعتماده؛ يجب أن يمر طلب التنفيذ عبر بوابة Runtime مسجلة ومقيّدة.

## الوضع الحالي

تعمل طبقات Agent Command Hub على استضافة تطبيق مُدارة، ولا تمنح مساحة المشروع Docker أو عزل عمليات نظام تشغيل قابل للاعتماد لتنفيذ شيفرة غير موثوقة. لذلك تبقى بوابة Runtime في وضع `environment_required` وتعيد طلباً محجوباً مع سجل تدقيق، بدلاً من تشغيل `shell` أو تثبيت حزم أو استخدام الشبكة.

## متطلبات البيئة الفعلية

| عنصر | شرط التنفيذ |
| --- | --- |
| العزل | حاوية قصيرة العمر أو VM لكل تنفيذ، غير مميزة ولا تشارك نظام ملفات التطبيق. |
| Workspace | نسخ الملفات المطلوبة فقط إلى مسار عمل مؤقت؛ يمنع الربط الرمزي والمسارات الأب. |
| الشبكة | معطلة افتراضياً؛ تفتح فقط بقائمة سماح موثقة إذا وافق المستخدم. |
| الموارد | CPU وذاكرة ومدة تنفيذ وحدّ لحجم الإخراج محددة لكل عملية. |
| الأسرار | لا تمرر مفاتيح التطبيق أو Git أو بيانات الاعتماد إلى بيئة المستخدم. |
| الأثر | يحفظ سجل الطلب والنتيجة والملخص ومحددات البيئة، لا الأسرار. |

## سياسة مستعرض Workspace

يعرض المستعرض الملفات الافتراضية المملوكة للمشروع ضمن `source/` و`docs/` و`tests/` و`artifacts/` و`memory/` و`logs/`. يمكنه قراءة المحتوى المحفوظ وتحديثه عبر واجهات API المحمية فقط. لا يعرض مسارات نظام التشغيل، ولا ينفذ محتوى الملف، ولا يفسر Markdown أو JavaScript كأوامر.

> لتفعيل تنفيذ شيفرة المستخدم لاحقاً، يلزم ربط عامل ببيئة نظام تشغيل معزولة مخصصة والتحقق من متطلبات الجدول أعلاه. يبقى التفعيل خارج التطبيق محجوباً حتى ذلك الحين.

# عقد أوامر العامل المُدار

## ما تم ربطه الآن

يرسل التطبيق أمر تشغيل مشروع إلى API محمية. يتحقق الخادم من ملكية المشروع، ثم يحفظ صفاً في جدول `execution_commands` ويكتب حدثاً من نوع `EXECUTION_COMMAND_QUEUED`. لا يعتمد الأمر على بقاء شاشة الجوال مفتوحة، وتظهر رسالة تأكيد في شاشة المشاريع بعد وضعه في القائمة.

| الحقل | الغرض |
| --- | --- |
| `command` | `run_project` أو `run_task` أو `resume_task` |
| `status` | `queued` ثم `claimed` ثم `completed` أو `failed` أو `cancelled` |
| `attempt_count` و`max_attempts` | ضبط إعادة المحاولة في العامل الدائم |
| `lease_owner` و`leased_at` | حجز المهمة لعامل واحد وإتاحة اكتشاف القفل المنتهي |
| `payload` | تعليمات نصية محددة للمشروع أو المهمة |

## ما يتطلبه العامل المُدار

بعد تفعيل الاستضافة الدائمة، يضاف عامل واحد خفيف في عملية الخادم نفسها أو خدمة عاملة متصلة بقاعدة البيانات. يجب أن يلتقط فقط الأوامر ذات `status = queued`، ويحوّلها بعملية حجز ذرية إلى `claimed`، ثم يمررها إلى Runtime بعد إنشاء Workspace.

> العامل لا يجب أن يملك صلاحية shell أو Git أو شبكة خارجية في هذه المرحلة. الأمر يُسجل فقط حتى توجد Workspace وRuntime وبوابة سياسة جاهزة.

## تفعيل الاستضافة الدائمة

استخدم إعداد **Always On / Reserved Hosting** من واجهة المشروع لتبديل الخادم من وضع الطلبات القصيرة إلى عملية واحدة دائمة تعمل 24/7. هذا يسمح بحلقة انتظار خفيفة وعامل لطابور الأوامر، لكنه محدود بـ1 vCPU و512MB ولا يناسب Docker أو Sandbox ثقيلة. السعر مبني على الاستهلاك، ويصل سقفه التقريبي عند الاستهلاك الكامل المستمر إلى 37.50 دولاراً شهرياً قبل الرصيد المجاني البالغ 10 دولارات؛ كما تحاسب الشبكة والتخزين حسب الاستخدام.

## الترتيب التالي الآمن

1. تفعيل الخدمة الدائمة وإرسال أمر مشروع من التطبيق.
2. بناء Workspace مقيّد لكل مشروع.
3. إضافة عامل يلتقط الأوامر ويحجزها ويسجل heartbeat فقط.
4. إضافة Runtime جاف ينشئ خطة وأحداثاً بلا أوامر نظام.
5. إضافة أدوات قراءة وكتابة مقيدة، ثم Sandbox بعد سياسة الموافقات.

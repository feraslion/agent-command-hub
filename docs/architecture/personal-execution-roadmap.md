# خارطة التنفيذ الشخصية

## الهدف

تتحول المنصة تدريجياً من لوحة متابعة على الهاتف إلى مهندس AI شخصي: يختار المستخدم مشروعاً، يرسل طلباً، ثم يستمر التنفيذ في بيئة مقيدة إلى أن يصل إلى اختبار ومراجعة أو يطلب موافقة بشرية لإجراء حساس.

| المرحلة | المخرج القابل للتحقق | بوابة الانتقال |
| --- | --- | --- |
| 1. البيانات وAPI | مشروع ومهمة محفوظان، وسجل أحداث وموافقات وتكلفة حقيقية | لا تعتمد شاشة المشروع على قائمة محلية افتراضية |
| 2. Workspace | مساحة محددة لكل مشروع تضم source وdocs وtests وartifacts وlogs وmemory | لا يستطيع التنفيذ الكتابة خارج مساحة المشروع |
| 3. Runtime وTools | سبعة وكلاء وأدوات مقيدة للملفات وGit والاختبار والبناء | لكل فعل إدخال ومخرج وسجل قرار |
| 4. Sandbox وTask Engine | حالات المهمة والتنفيذ المعزول وإعادة المحاولة المحدودة | فشل الاختبار يؤدي إلى Debug ثم Retest |
| 5. Worker وQueue | التنفيذ يبقى عاملاً بعد إغلاق الهاتف | المهام لا تعتمد على جلسة تطبيق الجوال |
| 6. Memory وModel Router | قرار المشروع محفوظ، وتكلفة كل استدعاء موثقة | لا تتعارض القرارات بين الوكلاء بلا سجل |
| 7. Git وRealtime | ملخص تغييرات واختبارات، وتحديث حي للتطبيق | لا Push أو Deploy تلقائي بلا سياسة موافقة |
| 8. اختبار حقيقي | مشروع صغير ثم مستودع فعلي من المستخدم | نجاح Plan → Code → Test → Fix → Build → Review |

## سياسة الموافقة الأساسية

| المستوى | أمثلة | الإجراء |
| --- | --- | --- |
| تلقائي | قراءة الملفات، التحليل، تشغيل الاختبارات، إصلاح بسيط | ينفذ ويوثق في السجل |
| مراجعة | تبعية جديدة، تغيير واسع، قرار معماري | يسجل طلباً قابلاً للقبول أو الرفض |
| موافقة صريحة | حذف بيانات، نشر، Push حساس، إعداد خطير | يتوقف التنفيذ حتى قرار المستخدم |

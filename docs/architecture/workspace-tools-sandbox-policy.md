# سياسة Workspace والأدوات وSandbox

## المبدأ التشغيلي

تعتمد المرحلة الحالية على **Workspace افتراضية دائمة داخل قاعدة البيانات**، وليست على مسارات نظام التشغيل. يحمي هذا الاختيار بيانات المشاريع من الوصول خارج نطاق المشروع، ويجعلها قابلة للتتبع والاستعادة ضمن البنية المستضافة الحالية. لا تملك هذه الطبقة صلاحية shell أو Git أو الشبكة أو العمليات الفرعية.

## نطاق Workspace

لكل مشروع Workspace واحدة فقط، بمجلدات افتراضية ثابتة:

| المسار الأعلى | الاستخدام المسموح |
| --- | --- |
| `source/` | نصوص المصدر والتعديلات المقترحة. |
| `docs/` | المتطلبات والقرارات والتوثيق. |
| `tests/` | مواصفات الاختبارات ونتائجها النصية. |
| `artifacts/` | مخرجات قابلة للمراجعة، بلا ملفات تنفيذية. |
| `memory/` | ذاكرة المشروع والملخصات والقرارات. |
| `logs/` | سجلات الأدوات والمحرك وSandbox. |

تُرفض المسارات المطلقة، وأي مسار يحوي `..` أو محرفاً صفرياً أو دليلاً أعلى غير معتمد. تكتب الأدوات ملفاً واحداً في كل فعل، وتسجل القراءة والكتابة والرفض في سجل تدقيق دائم.

## محرر الملفات ومراجعة الفروقات

يعرض مستعرض Workspace لغة الملف وفق امتداده ويقدم معاينة نصية مميزة للـ TypeScript وJavaScript وJSON وMarkdown وCSS وHTML وShell. عند اختيار وضع التحرير، تبقى المسودة محلية في الواجهة ولا تكتب إلى Workspace. يعرض وضع **الفروقات** الإضافات والحذف سطراً بسطر، مع عداد موجز للتغييرات؛ ولا يظهر زر **اعتماد وحفظ** إلا إذا اختلفت المسودة عن النسخة المحفوظة.

> التمييز الرمزي للقراءة والمراجعة فقط. لا يفسر المحرر محتوى الملف كأوامر، ولا يسمح الحفظ بتجاوز سياسة المسار أو حدود حجم المحتوى.

## سياسة الأدوات

| الأداة | الحالة | السياسة |
| --- | --- | --- |
| قراءة ملف افتراضي | تلقائي | محصورة داخل Workspace المملوكة للمشروع. |
| كتابة ملف افتراضي | مراجعة | تسجل المحتوى السابق واللاحق في الأثر وسجل التدقيق؛ لا تنفذ في النظام. |
| الاختبار المنطقي | تلقائي | يفحص اكتمال الخطة وتكامل Workspace وسياسة المسار، بلا تشغيل شيفرة مستخدم. |
| Git أو Push | موافقة صريحة | بوابة منطقية فقط؛ لا يوجد مستودع أو أمر Git في هذه المرحلة. |
| نشر أو حذف | موافقة صريحة | يسجل طلباً ويظل محجوباً حتى تتوفر بيئة تنفيذ معتمدة. |

## حدود Sandbox الحالية

Sandbox الحالية **منطقية وليست حاوية نظام تشغيل**. تفحص حدود المسارات وسياسة الأداة ووجود اعتماد مطلوب، ثم تنتج نتيجة قابلة للتتبع. لا تشغل اختبارات حقيقية لشيفرة Workspace، ولا تنشئ Docker أو عملية معزولة. يتطلب تشغيل شيفرة غير موثوقة لاحقاً بيئة نظام تشغيل مخصصة ومعزولة قبل السماح بها.

> لا تتحول أي خطة إلى تعديل خارجي أو Git أو نشر تلقائي. لا بد من تسجيل مستوى الموافقة المناسب، ثم توفير بيئة تنفيذ مستقلة قبل تشغيل أي أمر فعلي.

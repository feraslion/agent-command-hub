# استجابة التحقق البرمجي لتقرير الفحص

**التاريخ:** 21 أغسطس 2026  
**النطاق:** تحقق مباشر من الشيفرة والأصول في Agent Command Hub، ثم إصلاح المخاطر القابلة للمعالجة من دون جهاز Runner أو مفاتيح إصدار.

## النتيجة

أكد التحقق البرمجي ثلاث ملاحظات عالية الأولوية في التقرير المرفق: روابط أيقونات رمزية خارج المشروع، وسياسة CORS كانت تعكس `Origin` مع اعتماد الكوكيز، وتسجيل أجزاء من رموز الجلسة أو OAuth في سجلات العميل. عولجت الملاحظات الثلاث في هذا الإصدار، مع اختبارات تمنع عودتها.

| الملاحظة | نتيجة التحقق | الإجراء المنفذ | الدليل الآلي |
| --- | --- | --- | --- |
| أصول التطبيق روابط رمزية | مؤكدة؛ كانت أربعة ملفات PNG تشير إلى مسار خارجي | استبدلت بنسخ PNG حقيقية داخل `assets/images/` | `security-hardening.test.ts` يتحقق من عدم وجود symlink وتوقيع PNG |
| CORS يعكس أصل الطلب | مؤكدة في `server/_core/index.ts` | أضيفت قائمة Origins صريحة للنطاق المنشور وlocalhost ومعاينة Expo ومتغير `CORS_ALLOWED_ORIGINS` | `cors-policy.test.ts` يثبت قبول المعاينة المصرح بها ورفض أصل عشوائي |
| سجلات تكشف أجزاء اعتماد | مؤكدة في auth وAPI وOAuth callback | أزيلت مقاطع token/code/state وسجل `Set-Cookie` وعنوان URL ذي query | `security-hardening.test.ts` يمنع أنماط التسريب المعروفة |

## سياسة CORS الجديدة

لا يرسل الخادم الآن ترويسات الاعتماد إلا عندما يطابق `Origin` قائمة مسموحة صراحة. تشمل القائمة افتراضياً نطاق التطبيق المنشور و`localhost:8081` و`127.0.0.1:8081`، وتضيف تلقائياً نطاق معاينة Expo من متغيرات البيئة. يمكن إضافة نطاقات موثوقة فقط عبر قائمة مفصولة بفواصل في `CORS_ALLOWED_ORIGINS`.

> الطلبات بلا `Origin`، مثل Runner المحلي وفحوص الصحة والطلبات من المصدر نفسه، لا تحتاج ترويسات CORS وتبقى قابلة للوصول إلى مساراتها. أما طلب `OPTIONS` من Origin غير مصرح به فينتهي بـ `403`.

## بنود مقصودة التأجيل

| البند | سبب التأجيل | معيار الإغلاق |
| --- | --- | --- |
| Docker وRunner الحقيقي | يحتاج جهاز المالك وصلاحية Docker؛ لا يمكن إثباته من بيئة الجوال أو المحاكاة | صورة TypeScript وSmoke و`--check-config` ونبضة وطلب Runtime معتمد موثقة بلا أسرار |
| Gradle وAndroid فعلي | يحتاج Android SDK وجهازاً أو خدمة بناء مهيأة | بناء release تجريبي وفتح التطبيق على جهاز فعلي |
| توقيع Android الإنتاجي | يتطلب keystore وبيانات اعتماد لا تحفظ في Git أو المحادثة | إعداد توقيع إصدار عبر مخزن أسرار موثوق، ثم بناء موقّع صالح للتوزيع |

## تحسينات لاحقة غير حاجزة

ينبغي معالجة هوية حزمة المشروع المتبقية (`app-template`) وتقليل استخدام `any` وفصل الملفات الكبيرة تدريجياً بعد إثبات Runner الفعلي. لا تعد هذه البنود بديلاً عن إثبات الجهاز أو شرطاً لتشغيل QA المقيد؛ لكنها تحسن قابلية الصيانة والاستعداد للإصدار.

## التحقق المنفذ

نجحت الحزمة الكاملة: **119 اختباراً**، وفحص TypeScript، وLint، وبناء الخادم. لم يُثبت هذا التحقق تشغيل Docker الحقيقي، ولا يسمح بتفعيل محرك خارجي أو تنفيذ QA فعلي خارج الحدود الحالية.

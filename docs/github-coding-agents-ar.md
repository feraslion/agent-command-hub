# وكلاء برمجة GitHub المحكومون

هذا المستودع جاهز الآن لاستقبال مساهمات وكلاء برمجة عبر فروع وطلبات سحب. لا يؤدي وجود التعليمات أو القوالب إلى تثبيت تطبيق GitHub أو منح أي صلاحية جديدة تلقائياً.

| الوكيل | دوره المقترح | التفعيل المطلوب من المالك | حد الأمان |
|---|---|---|---|
| Jules | تنفيذ مهمة صغيرة من Issue أو من واجهته ثم إنشاء فرع وPR | ربط حساب GitHub مع Jules وتفويض هذا المستودع فقط | مراجعة PR يدوياً؛ لا دمج تلقائي. |
| GitHub Copilot coding agent | مسودات تغييرات وفق تعليمات المستودع | اشتراك/إعداد GitHub مناسب وتفعيل الوكيل للحساب أو المستودع | يسترشد بملف `.github/copilot-instructions.md`؛ لا يتجاوز حماية `main`. |
| CodeRabbit | مراجعة تغيرات وكلاء البرمجة داخل PR | تثبيت GitHub App مع اختيار هذا المستودع فقط | راجع أذونات القراءة/الكتابة قبل الحفظ؛ اعتبر ملاحظاته غير موثوقة إلى أن تراجعها. |
| Dependabot | تحديثات تبعيات صغيرة في PRs | تفعيل إعداد GitHub المدمج عند الحاجة | لا تعتمد التحديثات إلا بعد نجاح الفحوص ومراجعة التغييرات. |

## تشغيل Jules

بعد ربط GitHub من حساب المالك ومنح Jules حق الوصول إلى **هذا المستودع فقط**، افتح Issue باستخدام القالب `مهمة Jules محكومة` وأضف تسمية `jules`. وفق وثائق Jules، يختار الوكيل المستودع والفرع ثم يعمل على مهمة محددة، وينشئ فرعاً يمكن فتح PR منه للمراجعة [1]. لا تستخدمه لمهمة واسعة أو لتغيير إعدادات النشر أو الأسرار.

## مسار المراجعة المقترح

1. يفتح المالك Issue محدوداً بمعايير قبول.
2. ينفذ Jules أو Copilot المسودة في فرع منفصل.
3. يراجع CodeRabbit أو مراجع بشري فرق PR.
4. تُشغّل فحوص الجودة المطلوبة.
5. يقرر المالك الدمج يدوياً بعد مراجعة الأثر.

> لا يمنح هذا المسار الوكلاء حق الدمج أو النشر أو الوصول إلى مفاتيح البيئة.

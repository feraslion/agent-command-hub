# تحقق E2E من Runner المحلي

## النتيجة الحالية

يوجد اختبار E2E قابل للإعادة يشغّل **عميل Runner الحقيقي** مرة واحدة عبر `--once`، لكنه يستبدل Docker والخادم بمثيلين محليين مراقبين. لا يستخدم الاختبار قاعدة الإنتاج، ولا جهاز مالك، ولا Docker حقيقياً. لذلك يثبت تسلسل البروتوكول والحواجز في الكود، ولا يثبت بعد اتصال جهاز المالك أو إعداد Docker الفعلي.

| المسار | الإثبات الآلي | النتيجة المتوقعة |
|---|---|---|
| الجاهزية والنبض | صورة Docker الوهمية + `/heartbeat` | يعلن Runner قدراته ولا يكشف الرمز. |
| الحجز والتنفيذ | `/claim` يعيد برنامج JavaScript آمن | يستدعي العميل Docker مع شبكة معطلة وقراءة فقط وإسقاط القدرات. |
| حزمة TypeScript | `/claim` يعيد ملفين مع استيراد نسبي | يقبل Runner الاستيراد النسبي الثابت فقط ويستخدم الصورة المثبتة `agenthub-runner-ts:5.7.3`. |
| النتيجة | `/report` بعد التنفيذ | تُرسل حالة `completed` وخرج محدود. |
| عدم وجود عمل | `/claim` يعيد `null` | لا ينشئ العميل تقريراً أو حاوية وهمية. |
| حمولة خبيثة | مسار خارج `source/` أو `tests/` | يرفضها Runner قبل Docker ثم يبلغ بالفشل. |
| مصادقة فاشلة | `401` للنبض | ينتهي Runner ولا يحاول الحجز. |

## تشغيل الاختبار المعزول

```bash
pnpm test -- tests/local-runner-e2e.test.ts
```

الاختبار يجمع وسائط Docker الوهمية ويتحقق تحديداً من `--network none` و`--read-only` و`--cap-drop ALL` و`no-new-privileges`. لا ينبغي اعتبار مخرجه تفويضاً لتشغيل محرك خارجي؛ إنه شرط قبول برمجي فقط.

## بروتوكول الجهاز الحقيقي

يتطلب هذا الاختبار جهاز المالك الذي سيحتضن Runner، وDocker daemon عاملاً، والصورتين `node:22-alpine` و`agenthub-runner-ts:5.7.3`، وملف `.env.runner` صالحاً. لا تضع الرمز في المحادثة أو Git.

1. شغّل `runner/device/run-local-runner.sh --config /path/.env.runner --check-config` على جهاز المالك. يجب أن يثبت الأداة والصورتين من دون كشف الرمز.
2. أنشئ طلب Runtime صغيراً معتمدًا من التطبيق، ثم شغّل `run-local-runner.sh --config /path/.env.runner --once`.
3. راجع Runtime في التطبيق: `heartbeat` حديث، طلب واحد انتقل من `queued` إلى `completed` أو `failed` مع سبب، ولا توجد كتابة Workspace أو Git أو اتصال شبكة للحاوية.
4. نفّذ حالة رفض: اطلب مساراً محظوراً أو حمولة مخالفة للسياسة. يجب ألا تبدأ حاوية، ويجب تسجيل الرفض.
5. خزّن النتيجة المنقحة في سجل المشروع. لا تفعّل محركاً خارجياً قبل نجاح الحالات الأربع على الجهاز نفسه.

> لا يمكن لهذا المستودع تشغيل خطوة الجهاز الحقيقي بدلاً من المالك: الجهاز والرمز وDocker المقيدان محلياً خارج بيئة المشروع عمداً.

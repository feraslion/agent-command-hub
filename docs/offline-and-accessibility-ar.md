# القراءة دون اتصال والوصولية

## القراءة دون اتصال

يحفظ التطبيق آخر نتائج قابلة للقراءة من المشاريع والمهام والأحداث والموافقات وطلبات Runtime في تخزين محلي. عند غياب الإنترنت، يظهر شريط حالة واضح ويعرض النسخة المخزنة فقط. لا توجد طابور مزامنة للأفعال المتغيرة في هذه المرحلة؛ هذا مقصود لتجنب تكرار قرار أو تعديل عند عودة الاتصال.

| الحالة | السلوك |
| --- | --- |
| متصل | تُحدّث الاستعلامات الحية ويُحدّث المخبأ المحلي بعد وصول بيانات قابلة للقراءة. |
| دون اتصال | تُعرض آخر حالة محفوظة، وتبقى المرشحات والتنقل متاحة. |
| عودة الاتصال | تعود الاستعلامات العادية للتحديث؛ لا تُعاد أي موافقة أو كتابة أو أمر مؤجل. |

تمنع الواجهة صراحةً اعتماد ورفض القرارات، تعديل Workspace، طلب Pull Request، وإنشاء طلبات تنفيذ معزول أو متعدد الملفات في وضع عدم الاتصال.

## الوصولية والمسارات العميقة

تحتوي الأفعال الحرجة على أدوار وتسميات وصولية، ومنها اعتماد ورفض الموافقة، حفظ Workspace، طلب Runtime وطلب Pull Request. يعلن شريط الوضع دون اتصال نفسه كتنبيه، ويشرح سبب تعطيل الأفعال بدل إخفائها.

ينشئ المسار `approval/[approvalId]` رابطاً عميقاً إلى قرار محدد. تستخدم بطاقات تنبيه الموافقة هذا المسار؛ ويعيد المسار التحقق من أن القرار موجود في صندوق المالك الحالي قبل عرضه. يبقى القرار متوقفاً عن التغيير من الرابط نفسه عند عدم وجود اتصال.

# قوالب أدوار Agent Command Hub

تستكمل هذه القوالب `docs/agent-system-prompt-ar.md` ولا تتجاوزه. استخدم القالب المتخصص عند استدعاء الدور المطلوب، ومرر له السياق الأدنى الموضح في الوثيقة بدلاً من إعطائه صلاحيات أو ملفات خارج نطاق الخطوة.

| الدور | الملف | المخرج الأساسي | لا يفعل |
| --- | --- | --- | --- |
| Planner | `planner-system-prompt-ar.md` | خطة خطوات واعتماديات ومستويات موافقة ومعايير قبول. | لا يكتب شيفرة أو ملفات. |
| Coder | `coder-system-prompt-ar.md` | مسودة تعديل وفرق سطري ومؤشرات حساسية. | لا يشغل الشيفرة أو يحفظ التعديل الحساس مباشرة. |
| QA | `qa-system-prompt-ar.md` | قرار جودة وملاحظات مرتبة وقرار Task Engine مقترح. | لا يدعي تشغيل اختبارات ولا يعتمد التعديلات الحساسة. |

## التسلسل المقترح

1. يمرر Orchestrator الأمر والسياق إلى **Planner**؛ فينتج خطة قابلة للمراجعة.
2. بعد السماح بالخطوة البرمجية، يمرر Orchestrator سياق الملف والخطوة إلى **Coder**؛ فينتج مسودة وفرقاً.
3. يراجع **QA** الفرق ومعيار القبول والفحوص المتاحة؛ فيرفع ملاحظات أو يطلب بوابة قرار.
4. لا يتحول أي قرار منطقي إلى تنفيذ نظامي أو Git أو نشر من هذه القوالب؛ تتطلب تلك الأفعال بيئة Runtime معزولة وقدرة فعلية وموافقة مطابقة للسياسة.

> مرر قيمة `RUNTIME_CAPABILITIES` كما هي في الواقع. إذا كانت `canExecuteUserCode=false`، يجب على الأدوار الثلاثة وصف التحقق على أنه منطقي فقط.

## تعيين القوالب في التطبيق

تتيح شاشة **الوكلاء** اختيار أحد القوالب الثلاثة لكل وكيل وحفظ تعليمات مخصصة قصيرة. تحفظ التعليمات كملحق للقالب الأساسي ولا تستبدله؛ لذلك تبقى حدود Workspace والموافقات وSandbox غير قابلة للإزالة من خلال التخصيص النصي.

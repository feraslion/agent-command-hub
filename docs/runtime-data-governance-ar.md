# سياسة بيانات Runtime

تطبق هذه السياسة على **سجل Runtime** ومخرجاته المعروضة أو المصدرة. هدفها جعل المراقبة مفيدة من دون تحويل التطبيق إلى مخزن دائم لمخرجات حساسة أو مفاتيح تشغيل.

| المجال | السياسة المطبقة | الأثر العملي |
|---|---|---|
| `stdout` و`stderr` داخل Runtime | يقتطع Runner الناتج عند **8,000 حرف** لكل قناة قبل التخزين. | تمنع تضخم قاعدة البيانات وتحد من مساحة تعرض المخرجات. |
| عرض ومراجعة السجل | تعرض لوحة الصحة أن نافذة الاحتفاظ المستهدفة هي **30 يوماً**. | يستدل المالك على أن السجل تشغيلي قصير الأمد وليس أرشيفاً دائماً. |
| تصدير السجلات | يقتطع كل حقل مخرج أو سبب إلى **1,500 حرف**. | يقلل مشاركة النصوص الطويلة أو العرضية. |
| تنقيح النص | تحجب الأنماط الشائعة لـ `token` و`secret` و`password` و`api_key` و`authorization`، بما فيها قيم URL. | لا يضمن الكشف الكامل لكل سر؛ يجب عدم وضع أسرار في الشيفرة أو المخرجات أصلاً. |
| أدلة المشروع | تُصدر المراجع والملخصات فقط بعد التنقيح والاقتطاع؛ لا تصدر Runner keys أو متغيرات البيئة. | يبقى التصدير صالحاً للمراجعة مع تقليل السطح الحساس. |

> **قرار الأمان:** لا يحذف التطبيق سجلات موجودة تلقائياً في هذه المرحلة. الحذف الفعلي عملية مدمرة يجب أن تمر بمراجعة مستقلة وباختبار استعادة تجريبي قبل تفعيلها.

## إجراء المالك

استخدم زر **تصدير السجل المنقح** من Runtime أو **تصدير الأدلة المنقحة** من حوكمة المشروع عند الحاجة إلى مشاركة دليل. راجع الناتج قبل إرساله؛ التنقيح دفاع إضافي وليس بديلاً عن إدارة الأسرار الصحيحة.
